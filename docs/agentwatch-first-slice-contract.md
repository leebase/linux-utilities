# Overview

`agentwatch` is a small, auditable Linux C17 command-line supervisor for one requested command and the descendants that command creates. Its first vertical slice becomes a child subreaper with `prctl(PR_SET_CHILD_SUBREAPER, 1)`, starts exactly one command, observes the resulting descendant tree through bounded `/proc` scans, forwards termination when its deadline expires or it is interrupted, and synchronously reaps every child adopted into its process. It has no runtime dependency beyond libc and Linux interfaces, creates no persistent state, and writes no normal operational output.

The operational interface is `agentwatch [--timeout SECONDS] [--grace SECONDS] -- COMMAND [ARG...]`. `--timeout` is optional; without it the command has no deadline but remains interruptible. `--grace` defaults to 5 seconds and controls the bounded interval between `SIGTERM` and `SIGKILL`. `COMMAND` is executed directly with `execvp`; no shell is inserted. Sole-argument `--help` and `--version` are informational successes. The initial implementation target is `build/agentwatch`.

# Problem

Commands run by build agents and automation frequently create grandchildren, detach helpers, or leave zombies. A wrapper that waits only for its immediate child can report completion while work remains, and a wrapper that identifies processes only by PID can signal an unrelated process after PID reuse. Timeouts and terminal interruptions also need one predictable cleanup path: stop the whole known tree, reap adopted children, and communicate the reason for termination with a stable status.

This slice supplies that narrow lifecycle boundary without pretending to be an init system. The root child is placed in its own process group before execution, while subreaper adoption and bounded `/proc` observation cover descendants that change process group. Observation is advisory and race-aware: `waitpid` is authoritative for children, process identities include Linux start time, and uncertain or disappearing procfs records never authorize signaling a PID whose identity has not been revalidated.

# Constraints

The implementation shall use ISO C17 plus Linux/POSIX interfaces and compile with `_GNU_SOURCE` or an equivalent declaration environment for `prctl`. Startup order is fixed: validate arguments and numeric bounds; install handlers; call `prctl(PR_SET_CHILD_SUBREAPER, 1)`; create a close-on-exec error pipe; `fork`; place the child in a new process group; and execute `COMMAND` with `execvp`. The child writes the captured `execvp` errno to the error pipe and exits if execution fails. The parent must distinguish this handshake from a command that successfully starts and later exits `127`.

`SECONDS` is a strict base-10 finite value in `0.001..86400.000`, with no sign, exponent, suffix, whitespace, NaN, or infinity; repeated options, missing values, missing `--`, or an empty command are invalid. Time is measured with `CLOCK_MONOTONIC`. The deadline begins after successful `fork`; command-start handshaking remains subject to that deadline. `SIGINT`, `SIGTERM`, and `SIGHUP` handlers only record the first interruption and wake the main loop through a self-pipe; `SIGCHLD` also wakes the loop. The utility blocks or sequences these signals around shared-state transitions so none is lost between observation and sleep.

The direct child begins a distinct process group. On timeout or interruption, `agentwatch` sends `SIGTERM` to that group and to every separately identified live descendant, continues observing and reaping during the grace period, then sends `SIGKILL` to revalidated survivors. Duplicate targets are harmlessly suppressed. Signals are never broadcast with `kill(-1, ...)`, and the supervisor never signals itself. Normal completion means the original command has terminated and no children remain for `waitpid`; descendants still running after the original command exits continue to be supervised and reaped.

Procfs work is explicitly bounded. At most 4096 identities are retained, each as `(pid, starttime)` parsed from `/proc/PID/stat`; scans occur no more often than once per 50 milliseconds and inspect at most 65536 numeric PID directory entries per scan. Parent links are accepted only from complete, size-bounded records of at most 4096 bytes. A candidate is connected to the root only through a chain of observed parent identities. Immediately before signaling an individual PID, its `starttime` is reread and must equal the retained value. Missing entries, `ENOENT`, and a process disappearing mid-read mean “gone,” not failure; malformed, oversized, permission-denied, or inconsistent records mean “unknown” and are never individually signaled. Process-group signaling remains permitted for the group created for the direct child.

All waitable children are drained with `waitpid(-1, ..., WNOHANG)` after every wake and until `ECHILD` before return. `EINTR` retries; other `waitpid`, clock, poll, pipe, allocation, `prctl`, `fork`, or required signal-operation failures are internal failures but still enter best-effort TERM/KILL cleanup. If tracking limits or hostile procfs data prevent complete individual discovery, the utility records partial observation, uses the owned process group, reaps everything it can, and returns the internal-failure status unless timeout, interruption, or command-start failure has the higher precedence specified below. Cleanup is bounded by the configured grace interval plus a final two-second reap ceiling; reaching that ceiling is an internal failure rather than an unbounded hang.

The closed hazard taxonomy is: `INVALID_ARGUMENTS` for syntax, arity, or numeric errors; `SUBREAPER_SETUP_FAILURE`; `SIGNAL_SETUP_FAILURE`; `COMMAND_START_FAILURE` for pipe, fork, process-group setup, or exec handshake failures; `TIMEOUT`; `INTERRUPTED`; `PROCFS_DISAPPEARED` for benign races; `PROCFS_UNTRUSTED` for malformed, hostile, inaccessible, truncated, or identity-inconsistent data; `TRACKING_LIMIT`; `PID_IDENTITY_CHANGED` for reuse detection; `SIGNAL_DELIVERY_FAILURE` other than benign `ESRCH`; `REAP_FAILURE`; `CLEANUP_INCOMPLETE`; and `INTERNAL_FAILURE` for remaining clock, poll, allocation, or invariant failures. These names are exhaustive for this slice. Diagnostics use the taxonomy name and escape untrusted bytes; procfs uncertainty is silent when cleanup and reaping nevertheless complete, but becomes status 125 when it makes completeness unknowable.

Exit status is deterministic. Status `2` means invalid arguments detected before a command starts; after a successful start, status `0..123` is the direct command's ordinary exit status, including 2. Status `124` means the deadline expired. Status `125` means an internal, observation, signaling, reaping, or incomplete-cleanup failure. Status `126` is reserved and is not emitted in this slice. Status `127` means the requested command could not be started. Status `128+N` means the original command terminated from signal `N`, or the supervisor received `SIGINT`, `SIGTERM`, or `SIGHUP`; an interruption takes precedence over timeout, which takes precedence over internal/cleanup failure, which takes precedence over the command result. A command ordinary exit of 124 or 125 is returned unchanged only when the corresponding supervisor condition did not occur; the diagnostic stream distinguishes wrapper failures. Command-start failure takes precedence over all conditions discovered after `fork`, except an interruption already recorded, and returns 127 after cleanup.

Explicit non-goals are general init-system or PID-1 behavior, daemon mode, service restart policy, multiple concurrent root commands, scheduled execution, resource accounting or enforcement, namespaces, cgroups, privilege changes, security sandboxing, log capture, output multiplexing, arbitrary process discovery, user-selected signals, broad process-management features, networking, remote control, telemetry, persistence, and background monitoring after `agentwatch` exits. The utility does not promise to control descendants that deliberately escape both the owned process group and all observable/reapable ancestry during kernel races; it fails closed when that uncertainty affects cleanup.

# Acceptance Checks

- **AC-1** — The built C17 utility accepts exactly `agentwatch [--timeout SECONDS] [--grace SECONDS] -- COMMAND [ARG...]`, plus sole `--help` and `--version`, rejects every documented invalid form with status 2, and distinguishes an `execvp` start failure (127) from a successfully started command that exits 127.
- **AC-2** — Before starting the command, the supervisor successfully enables `PR_SET_CHILD_SUBREAPER`; it creates a separate process group, supervises until the direct command and adopted children are gone, drains `waitpid(-1, ...)` through `ECHILD`, and returns the documented direct-command exit or signal status without zombies.
- **AC-3** — A monotonic timeout produces status 124 and a `SIGINT`, `SIGTERM`, or `SIGHUP` interruption produces `128+N`; both paths send `SIGTERM`, observe and reap during the bounded grace period, revalidate identities, escalate survivors with `SIGKILL`, and obey the documented precedence rules.
- **AC-4** — Descendant discovery respects the 4096-identity, 65536-entry, 4096-byte-record, and 50-millisecond scan bounds; tests cover disappearing, malformed, oversized, permission-denied, and inconsistent `/proc/PID/stat` observations without unsafe signaling or unbounded work.
- **AC-5** — PID reuse tests prove that retained `(pid, starttime)` identities are revalidated immediately before individual signaling, changed identities receive no signal, ancestry is established only through observed identity chains, and process-group signaling is limited to the group created for the requested command.
- **AC-6** — Fault-injection tests cover every member of the closed hazard taxonomy, including tracking exhaustion, signal-delivery errors, reap errors, setup failures, partial procfs visibility, and cleanup ceilings; outcomes use statuses 2, 124, 125, 127, or `128+N` exactly as specified and sanitize untrusted diagnostics.
- **AC-7** — The implementation and tests preserve all explicit non-goals, compile warning-free with GCC and Clang under `-Wall -Wextra -Wpedantic -Werror`, and pass applicable formatting, static-analysis, ASan, UBSan, Valgrind, unit, integration, regression, fixture, timeout, interruption, hostile-procfs, and zombie-reaping checks.
